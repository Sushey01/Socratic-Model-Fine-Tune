MEMORIZATION vs LEARNING — v7 4B Socratic tutor
================================================

Symptom
-------
The deployed model often sounds like a tutor (short question, "Let's work through this")
but is not tracking the student. In one Space chat, puberty jumped to plant tropism,
digestion, force, momentum, particle size, then motion — with the same openers reused.

This is memorization of high-frequency assistant templates, not Socratic reasoning
conditioned on the last user turn.


Evidence from the 2-epoch QLoRA run (~716 steps)
------------------------------------------------
Metric              Early (~step 30)     End (step 716)
Loss                ~1.28                ~0.10–0.13
Token accuracy      ~65%                 ~95–97%
Entropy             ~1.27                ~0.09–0.15

Loss fell below 0.5 by ~step 90 (still epoch 1). That is too fast for "learned to
tutor." It matches predicting easy repeated tokens: system-adjacent assistant
boilerplate ("Let's work through this:", "Let's think about this:").

ScienceQA (same 256-item slice, seed 42) barely moved:
  epoch 1 acc ~0.6719
  epoch 2 acc ~0.6758   (final eval acc 0.6836, SRI 0.9062)

Train loss kept falling in epoch 2 while held-out acc stayed flat. That is
overfitting to the train JSONL, not better generalization.

ScienceQA acc is an exam-letter score. SRI only checks that the MC gold text was
not pasted. Neither measures "stayed on puberty." Ice-float still leaked
"less dense" then asked a question.


Masking (do not misdiagnose)
----------------------------
train_qwen.py already sets TRL assistant_only_loss=True when the installed TRL
supports it. The MSI v9 run printed:

  Using SFTConfig(assistant_only_loss=True); keeping raw 'messages'

Confirm the same line at the top of the v7 / next train log. If it is there,
the defect is NOT "loss on the full transcript." Assistant-only loss still
trains every assistant token, including cloned openers.
